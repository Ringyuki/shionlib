## Shionlib の大容量アップロードシステムの紹介

### なぜ大容量アップロードシステムが必要なのか？

Shionlib の目標の一つは、あらゆる時代のビジュアルノベル／ギャルゲーの完全でコントロール可能なアーカイブを構築・維持することです。これは容易なことではありません。私たちの経験上、これを実現できるのは **コミュニティ主導** のモデルだけです。

そのため、すべてのユーザーに大容量ファイルのアップロード権限を開放するアップロードシステムを設計しました。

### アップロードのワークフロー

ローカルファイルを選択すると、ブラウザはファイルをチャンク（1 つあたり約 50 MB）に分割して Shionlib のサーバーへ 1 つずつ送信し、アップロードと同時に各チャンクとファイル全体の SHA-256 ハッシュを計算します。

すべてのチャンクのアップロードが完了すると、サーバーはファイル全体の SHA-256 ハッシュを再度計算し、ブラウザ側で計算したハッシュと比較します。一致すれば、アップロードは成功としてマークされます。

続いて、Shionlib のサーバーはアップロードが完了したファイルをチェックします。アーカイブと分割アーカイブは 7-Zip で全体をテストし、ファイルが完全で、破損しておらず、暗号化されていないことを確認します。アーカイブ内の実行ファイルは、さらにウイルススキャンにかけられます。

最後に、チェックに合格したファイルは Shionlib のストレージバケットに保存されます。1 つのリソースのすべてのファイルの保存が完了すると、リソースは自動的に公開され、サイト内メッセージが 1 件届きます。

### 課題

システム全体は細心の注意を払って設計する必要があります。もし誰かが何らかの方法で破壊を試みれば、許容できない結果を招きます。

- 非常に大きなファイルを大量に悪意をもってアップロードする行為。計画を超える大量のストレージを占有し、過大なストレージ費用の発生につながります。
- マルウェアを含むファイルを悪意をもってアップロードする行為。プロセス中にファイルの実行は行いませんが、ダウンロードしたユーザーに危険を及ぼす可能性があります。

システムを健全かつ持続的に運用するため、アップロード者ごとに **保存容量** の上限を設け、公開済みのリソースの数に応じて 3 つのランクに分けています：

| ランク                 | 条件                                               | 保存容量 |
| ---------------------- | -------------------------------------------------- | -------- |
| 新規アップローダー     | なし                                               | 50 GB    |
| 一般アップローダー     | 公開済みのリソースが 3 件                          | 300 GB   |
| 信頼済みアップローダー | 公開済みのリソースが 30 件、または管理者による付与 | 2 TB     |

保存済みのファイルとアップロード中のファイルの合計は、保存容量の上限を超えることができません。1 つのファイルは 30 GB を超えることができず、同時に進行中のアップロードの合計も 30 GB を超えることができません。リソースまたはファイルを削除すると、それが占めていた容量はすぐに解放されます。現在のランクと使用済みの容量は **マイアップロード** ページに表示されます。

より多くの容量が必要な場合は、信頼済みアップローダーになるための申請を管理者に行うことができます。

**次のいずれかに該当する場合は違反となり、システムが一定期間あなたのランクを引き下げるほか、アカウントを停止することもあります：**

- アップロードしたファイルにマルウェアが含まれていると管理者が確認した場合
- 他のユーザーがあなたのアップロードしたリソースを報告し、管理者がその報告を正当と認めた場合

## ファイルのアップロード

### 形式とファイル名のルール

ファイルは zip/rar/7z のアーカイブにまとめてからアップロードすることをお勧めします。アーカイブに**パスワードを設定することはできません**。

1 つのリソースには複数のファイルを含めることができます。分割アーカイブは、まとめ直さずにそのままアップロードできます。同じ組の分割ファイルは同じリソースに入れ、元のファイル名（`.part1.rar`、`.r00`、`.7z.001`、`.z01` など）を変えないでください。システムはファイル名から分割ファイルを識別し、すべての分割ファイルがアップロードされてからまとめてチェックします。

ファイル名を自分で整える必要はありません。リソースは既定で**規定のファイル名**を使用します。公開時に、サイトがゲームの作品情報とリソースの情報からファイル名を付け直します。形式は次のとおりです。

- `[発売日][ブランド] 原題 訳題 エディション [翻訳][パッチのバージョン] (形態).拡張子`

発売日・ブランド・タイトルは作品情報から取得し、訳題は中国語のリソースにのみ使用します。それ以外の項目はリソースの情報から取得し、内容のない部分は省略されます。括弧内の形態は、ディスクイメージの場合はその形式（`iso+mds` など。ファイルのチェックで判明します）、インストーラーとインストール不要の場合は `files` になります。例：

- `[160729][ゆずソフト] 千恋＊万花 [官方中文] (files).part1.rar`

規定のファイル名が使われるのは、リソースの最初のファイル（分割アーカイブの場合は同じ組のすべての分割ファイル）だけです。アップロード時のファイル名を残したい場合は、**規定のファイル名を使用** をオフにしてください。

言語、翻訳、翻訳グループ、パッチのバージョンなどの情報は、ファイル名ではなくリソースの情報（後述します）に入力してください。

### アップロードを開始する

サイドバー上部の **アップロード** ボタン、またはゲームページの **アップロード** ボタンをクリックして、アップロードページを開きます。

アップロードページでゲームとアップロードするファイルを選び、リソースの情報を入力します。ファイルを選ぶと、ページはファイル名から翻訳、翻訳グループ、パッチのバージョン、エディション、形態を読み取り、まだ入力されていない項目に入れます。各項目を確認してください。ページには、あなたの保存容量と、今回選んだファイルが占める容量が表示されます。

リソースの情報は次のとおりです。

- **プラットフォーム**、**言語** — 必須。複数選択可
- **エンジン** — プラットフォームに Android または iOS が含まれる場合は必須。そのリソースを動かすエンジンです
- **翻訳** — 言語に日本語以外が含まれる場合は必須：なし、公式翻訳、翻訳グループ、機械翻訳。翻訳グループを選んだ場合は **翻訳グループ** の名前を入力します（6 つまで。入力中にサイトに登録済みの翻訳グループが候補として表示されます）。翻訳グループまたは機械翻訳の場合は、**パッチのバージョン** と **公開ページ** も入力できます
- **エディション** — DL版、パッケージ版、Steam版と、初回限定版などのエディション名。任意
- **形態** — 必須：ディスクイメージ、インストーラー、インストール不要。チェックでアーカイブ内にディスクイメージが見つかった場合、形態は自動的にディスクイメージになります
- **同梱物** — フルコンプセーブ、特典。任意
- **説明** — リソースの補足説明。任意、255 文字まで。太字、ネタバレ、リンクを使用できます
- **ファイル名** — リソースの公開後のファイル名。前述の規定のファイル名を参照してください

![ゲームとファイルを選び、リソースの情報を入力する](/assets/images/upload-game-files/ja/upload-page@2x.webp)

**アップロードを開始** をクリックすると、ページは **マイアップロード** に移動し、ここで各ファイルのアップロードの進み具合を確認できます。アップロード中もサイト内のほかのページを閲覧できますが、アップロードが完了するまで、Shionlib のページをすべて閉じることはしないでください。

![「マイアップロード」でアップロードの進み具合を確認する](/assets/images/upload-game-files/ja/uploading@2x.webp)

**アップロードを一時停止** ボタンをクリックするといつでもアップロードを一時停止でき、あとで **アップロードを再開** ボタンをクリックすると続きからアップロードできます。

アップロードの中断を想定し、レジュームに対応しています。ページを閉じたり再読み込みしたりした場合は、**マイアップロード** に戻ると未完了のアップロードが表示されます。**ファイルを選び直す** ボタンをクリックして同じファイルを選ぶと、中断したところからアップロードを続けられます。24 時間を超えて進展のないアップロードは期限切れになります。

![ファイルを選び直してアップロードを続ける](/assets/images/upload-game-files/ja/resume-upload@2x.webp)

### チェックと公開

ファイルのアップロードが完了すると、システムはファイルのチェックと保存を開始します。進み具合は **マイアップロード** の **処理中** で確認でき、ファイルの横にはその時点の状態が表示されます：

| 状態             | 意味                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| チェック中       | ファイルが壊れていないか、安全かどうかを確認しています                                                     |
| 分割ファイル待ち | この組の分割ファイルがまだそろっていません。そろってからチェックします                                     |
| 保存中           | ファイルはチェックに合格し、保存しています                                                                 |
| 審査待ち         | ウイルススキャンで疑わしい内容が見つかり、管理者の審査を待っています                                       |
| チェック未完了   | システムがチェックを完了できなかったため、管理者に引き継ぎました。現時点で操作は不要です                   |
| チェック不合格   | ファイルが不完全である、破損している、パスワードが設定されている、または有害な内容を含むため、削除されます |

分割ファイルがそろっていない場合は、不足しているファイルと追加の期限がページに表示されます。期限内に **ファイルを追加** から追加してください。期限を過ぎると、この組のファイルは削除されます。

リソースは、公開されるまであなたにのみ表示されます。すべてのファイルの保存が完了すると、リソースは自動的に公開され、**マイアップロード** の **公開済み** に表示されます。
