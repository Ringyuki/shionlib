## Introduction to Shionlib's large-file upload system

### Why design a large-file upload system?

One of Shionlib's goals is to build and maintain a complete, controllable archive of visual novels/galgames across all eras. Achieving this is anything but easy. From our experience, only a **community-driven** model can make it possible.

Therefore, we designed an upload system that grants all users large-file upload permissions.

### Upload workflow

After you select local files, the browser slices each file into chunks (about 50 MB each) and sends them to Shionlib's servers one by one, computing the SHA-256 hash of every chunk and of the whole file while uploading.

Once all chunks have been uploaded, the server computes the SHA-256 hash of the whole file again and compares it with the hash calculated by the browser. If they match, the upload is marked as successful.

Next, Shionlib's servers check the uploaded file: archives and split archives are tested in full with 7-Zip to confirm that the file is complete, not damaged and not encrypted; executable files inside an archive also go through a virus scan.

Finally, files that pass the checks are saved to Shionlib's storage bucket. Once all files of a resource have been saved, the resource is published automatically and you receive a message on the site.

### Challenges

It is obvious that we must design the entire system with great care. If anyone attempts to disrupt it in any way, the consequences would be unacceptable.

- Maliciously uploading a large number of huge files. This would occupy far more storage than planned, potentially forcing us to pay excessive storage fees
- Maliciously uploading files that contain malware. Although we never execute files at any point in the process, such files could still pose risks to users who download them

To ensure the system can operate normally and sustainably, we set a **storage** limit for every uploader, in three tiers by the number of published resources:

| Tier             | Condition                                              | Storage |
| ---------------- | ------------------------------------------------------ | ------- |
| New uploader     | None                                                   | 50 GB   |
| Regular uploader | 3 published resources                                  | 300 GB  |
| Trusted uploader | 30 published resources, or granted by an administrator | 2 TB    |

Stored files and files being uploaded together cannot exceed the storage limit. A single file cannot exceed 30 GB, and the uploads in progress at the same time cannot exceed 30 GB in total either. After a resource or file is deleted, the space it occupied is released immediately. Your current tier and the space you have used are shown on the **My uploads** page.

If you need more space, you can ask an administrator to make you a trusted uploader.

**Note that any of the following is a violation, for which the system will lower your tier for a period of time, or even ban your account:**

- A file you uploaded is confirmed by an administrator to contain malware
- Other users report a resource you uploaded, and an administrator verifies that the report is valid

## Uploading files

### Format and file-naming guidelines

We recommend packaging the files as a zip/rar/7z archive before uploading. The archive **must not be password-protected**.

A resource can contain multiple files. Split archives can be uploaded directly without repacking: put the volumes of one set in the same resource and keep their original file names (such as `.part1.rar`, `.r00`, `.7z.001`, `.z01`). The system recognizes the volumes by their file names and checks them together once all volumes have been uploaded.

You do not need to tidy up the file names yourself. A resource uses the **canonical file name** by default: when it is published, the site renames the file from the game's entry and the resource information, in this format:

- `[release date][brand] original title translated title edition [translation][patch version] (form).extension`

The release date, brand and titles come from the game's entry, the translated title is used only for Chinese resources, and the rest comes from the resource information; a part without content is left out. The form in brackets is the format of the disc image for a disc image (such as `iso+mds`, found by the file check) and `files` for an installer or a portable game. For example:

- `[160729][ゆずソフト] 千恋＊万花 [官方中文] (files).part1.rar`

The canonical file name applies only to the first file of a resource, or to every volume of its set. To keep the name the file was uploaded with, turn off **Use the canonical file name**.

Fill in the language, the translation, the translation groups, the patch version and similar information in the resource information (see below), not in the file name.

### Start the upload

Click the **Upload** button at the top of the sidebar, or the **Upload** button on a game page, to open the upload page.

On the upload page, choose the game and the files to upload, then fill in the resource information. Once you choose the files, the page reads the translation, the translation groups, the patch version, the edition and the form from the file name and fills in the fields that are still empty; check each of them. The page shows your storage and how much of it the files chosen this time will take up.

The resource information consists of:

- **Platforms**, **Languages** — required; several can be chosen
- **Engine** — required when the platforms include Android or iOS: the engine that runs the resource
- **Translation** — required when the languages include one other than Japanese: None, Official translation, Translation group or Machine translation. For a translation group, enter the names of the **Translation groups**, at most 6; the groups already on the site are suggested as you type. For a translation group or a machine translation you can also enter the **Patch version** and the **Release page**
- **Edition** — Download edition, Package edition or Steam edition, and an edition name such as 初回限定版; optional
- **Form** — required: Disc image, Installer or Portable. When the check finds a disc image in the archive, the form becomes Disc image by itself
- **Extras** — Full CG save, Bonus content; optional
- **Note** — a supplementary note on the resource; optional, up to 255 characters, with bold, spoilers and links
- **File name** — the name the file will have once the resource is published; see the canonical file name above

![Choosing the game and the files and filling in the resource information](/assets/images/upload-game-files/en/upload-page@2x.webp)

After you click **Start uploading**, the page moves to **My uploads**, where you can follow the upload progress of each file. While uploading you can keep browsing other pages of this site, but do not close all Shionlib pages until the upload completes.

![Following the upload progress in "My uploads"](/assets/images/upload-game-files/en/uploading@2x.webp)

You can click the **Pause the upload** button at any time to pause the upload, and click the **Resume the upload** button later to continue.

We designed for possible interruptions and support resumable uploads. If the page is closed or reloaded, go back to **My uploads**, which then shows the uploads that have not finished; click the **Choose the files again** button and select the same files to continue uploading from where it stopped. An upload that makes no progress for more than 24 hours expires.

![Choosing the files again to continue the upload](/assets/images/upload-game-files/en/resume-upload@2x.webp)

### Checks and publishing

After the files finish uploading, the system starts checking and saving them. You can follow the progress under **Processing** in **My uploads**, where the current state of each file is shown beside it:

| State               | Meaning                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| Checking            | The integrity and safety of the file are being checked                                                     |
| Waiting for volumes | This set of volumes is not complete yet and is checked only once the missing volumes are added             |
| Saving              | The file has passed the checks and is being saved                                                          |
| Awaiting review     | The virus scan found something suspicious, and the file is waiting for an administrator's review           |
| Check not finished  | The system could not complete the check and has handed it to an administrator; no action is needed for now |
| Failed the check    | The file is incomplete, damaged, password-protected or contains harmful content, and will be removed       |

When a set of volumes is incomplete, the page lists the missing files and the deadline for adding them. Add them through **Add files** before the deadline; after the deadline, this set of files will be removed.

Until it is published, a resource is visible only to you. Once all files have been saved, the resource is published automatically and appears under **Published** in **My uploads**.
